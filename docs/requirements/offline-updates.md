# Offline Snapshot & Version Updates

## Overview

Percussion Studio ships as a static site (GitHub Pages) with no build step and
no service worker historically, so an installed home-screen shortcut could
keep running a stale cached bundle after a deploy. This spec defines the
atomic, versioned offline cache that makes every controlled load run exactly
one coherent app version — online and offline — and updates it without ever
mixing old and new files.

Implementation: `sw.js` (worker), `precache.json` (generated descriptor),
registration/reload policy in `js/app.js`, dependency vendoring in
`js/vendor/`.

## Guarantees

| Situation | Guarantee |
|---|---|
| Online, page controlled by the worker | The deployed version, verified asset-by-asset; no mixed versions possible |
| Offline | The complete last verified snapshot (shell, data, all sounds) |
| First load of a page running pre-service-worker code | May run an old bundle once; the worker installs, claims and aligns with one deferred reload |
| A deploy while a page is running | New snapshot prepared in the background; page reloads when idle (never during playback) |
| Deploy mid-download | Per-asset hash verification fails, the partial cache is discarded, the previous version keeps serving |
| Service workers unavailable / site data cleared | The app behaves as before (plain HTTP cache), no crash |

The one physical limit: offline, code that was never downloaded cannot be
fetched. Offline means "the last complete snapshot", not "the latest deploy".

## Snapshot descriptor (`precache.json`)

Generated by `tools/generate_manifest.py` (Python, no Node) alongside
`manifest.json`:

```json
{
  "version": "<sha256 over every asset hash, sorted by path>",
  "assets": [{ "path": "mobile.html", "hash": "<sha256>", "size": 7430 }, …]
}
```

Contents: `index.html`, `mobile.html`, `desktop.html`, `favicon.svg`,
`icons/**`, `js/**` (including `js/vendor/**`), `data/**` (YAML, WAV, SVG,
JSON), `manifest.json`, `docs/user-guide-*.md`. `sw.js` and `precache.json`
are excluded by design. `version` changes iff any shipped file changes, so a
regenerated-but-identical tree produces the same version.

## Worker model (`sw.js`)

- **State**: active manifest persisted in IndexedDB (`ps-sw-meta`); one
  CacheStorage snapshot per version (`ps-v<version>`).
- **Build (atomic)**: fetch `precache.json?ts=<now>` with `no-store` (busts
  browser and edge caches). For each asset, copy from the previous snapshot
  when `(path, hash)` matches, otherwise download with `cache: 'reload'` and
  verify SHA-256. Only after every asset verifies is the new snapshot made
  active and the previous one deleted. Failures leave the previous snapshot
  untouched.
- **Serve**: snapshot paths are served cache-first from the active version
  (path matching ignores the query, so `?rhythm=`, `?sw=1` work). Non-GET,
  cross-origin and unknown paths pass through. `sw.js` and `precache.json`
  are never served from the snapshot.
- **Checks**: `precache.json` is re-checked on navigation (throttled to
  5 minutes) and on demand via `{ type: 'ps-check-update' }`. When a new
  version verifies, clients receive
  `{ type: 'app-version-ready', version }`.
- **Lifecycle**: `install` → `skipWaiting()`; `activate` → `clients.claim()`
  + a forced update check, so the first controlled load converges in the
  same session.

## Page policy (`js/app.js`)

- Registration is skipped on `localhost`/`127.0.0.1` (the dev server serves
  `no-cache`) unless `?sw=1` is present; the E2E suite uses `?sw=1`.
- `app-version-ready` or a real `controllerchange` sets a pending reload.
  The reload runs only when `state.isPlaying` is false and no slider drag is
  active; otherwise it is retried on the next `render` (playback stop) or
  when the app returns to the foreground.
- The initial install's first claim does not reload by itself; alignment
  happens when the first snapshot finishes verifying (`app-version-ready`).
- All steps are best-effort: without service worker support (or on any
  failure) startup and playback behave exactly as before.

## Vendored dependencies

`mobile.html` / `desktop.html` load Tailwind and js-yaml from `js/vendor/`
instead of CDNs, so they are same-origin, hash-verifiable snapshot assets and
the app boots offline. See `js/vendor/README.md` for versions/licences.

## Development & release workflow

- The generator runs automatically with `launch_local.py` and the test
  server, so `precache.json` stays fresh locally.
- **Before committing any app/data change**: run
  `python3 tools/generate_manifest.py` and commit `manifest.json`,
  `data/rhythms/Batà/bata_metadata.json` and `precache.json` together. The
  snapshot version changes automatically; `sw.js` itself only changes when
  worker logic changes.
- E2E: all existing projects run with `serviceWorkers: 'block'`; the
  `service-worker` project runs with `'allow'` and exercises install,
  offline serving and the atomic swap (see `docs/testing.md`).
